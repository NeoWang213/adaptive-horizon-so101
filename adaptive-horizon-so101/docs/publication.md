# 后续资源上传与发布

当前版本只搭建研究项目介绍与资源占位，不包含新实现的 MLP、训练或部署流程。
先用私有仓库整理，再根据论文与数据分享安排决定何时公开。

## 上传位置

按场景上传时，先进入 [任务索引](../tasks/README.md)。物块放盒与笔放笔筒已有独立
入口；后续场景可复制 [新场景模板](../tasks/_template/README.md)，在各资源目录下
新增同名任务子目录。各场景的模型、数据、配置、演示与结果分别保存。

| 内容 | 目录 |
|---|---|
| ACT 模型说明与下载信息 | `models/act/` |
| 微调后的 π0.5 说明与下载信息 | `models/pi05/` |
| MLP 源码 | `research/adaptive_horizon/` |
| MLP 权重说明与下载信息 | `models/horizon_mlp/` |
| 两个任务的数据说明 | `data/block_to_box/`、`data/pen_to_holder/` |
| 标注、标签定义与数据划分 | `data/annotations/` |
| 评估数据、汇总表与图表 | `results/` |
| 演示视频说明与链接 | `media/demos/` |

每个资源目录的 `manifest.example.json` 是填写模板；复制为 `manifest.json` 后填入
真实信息。未填写的 `null` 表示尚未上传，不是有效下载地址。

## 大文件

建议模型与原始数据上传到 Hugging Face Hub 等版本化存储，并在资源清单中记录
repo_id/URL、固定 revision、文件名、许可与对应代码版本。
GitHub 放项目介绍、正式源码、配置、资源清单和小型实验结果。

模型权重与原始数据目录默认忽略二进制文件，仅保留 README 和 manifest JSON。
可以先把资源保存在本地占位目录，它们不会因此自动进入 Git 提交。
如选择 Git LFS 托管，先明确配额、文件规则和克隆方式，再有意调整忽略规则。

## 公开前

- 核对 README 中的状态与实际已上传内容一致，补上可用的下载和复现命令。
- 保留 LeRobot 原有版权声明和 Apache-2.0 许可证；核对模型与数据的独立许可。
- 排除 HF 缓存、凭据、本机标定、截图和训练临时产物，并检查实际提交文件。
- 后续若上传 Git LFS 大文件，检查它们能否从个人远程下载。当前介绍版本不包含 LFS 文件。
- 原论文完整引用待核对后补充；不预先写入未经验证的效果或创新性结论。
- 论文版本冻结时记录代码 tag、模型/数据 revision、实验配置和完整评估记录。

当前上传包只含介绍与占位目录，不包含上游 LeRobot 运行代码、Git 历史或自动发布工作流。
本地开发工作区保留原有代码和历史。后续发布源码时再配置本项目的测试与发布流程。
