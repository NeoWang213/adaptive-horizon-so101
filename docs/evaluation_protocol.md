# 评估设想：待实验方案确定后完善

## 比较对象

两个任务分别在 ACT 与微调后的 π0.5 上比较固定执行长度、简单规则调度和
MLP 调度。固定长度应覆盖短反馈间隔与长执行区间，由验证集确定参数。
策略间分别报告相对各自基线的变化。

## 主要指标

| 指标 | 记录要求 |
|---|---|
| 成功率 | 成功次数 / 全部尝试次数；补充置信区间 |
| 推理次数 | 真实策略动作块预测次数，区分缓存取动作 |
| 计算耗时 | 计入策略、MLP、额外特征提取；注明计时范围与硬件 |
| 完成时间 | 根据预先定义的成功条件测量；说明失败和超时处理 |
| 执行长度 | 每次选择的 horizon 及实际执行步数 |

减少调用次数、降低实际计算开销和提高任务完成速度分别验证。
离线分类准确率不等于实机任务成功率。

## 数据与尝试记录

按完整 episode 划分训练/验证/测试，记录数据、模型与代码版本。正式测试前固定
任务成功标准、超时、尝试次数、初始条件、控制频率及评估顺序。

失败、中断、人工干预和重新录制的尝试都应保留，避免仅统计被接受的视频。
原始日志建议包含 attempt_id、task、policy、method、outcome、policy_calls、
compute_time_s、completion_time_s、selected_horizons 和各资源版本。
这些是待实现的记录要求，目前没有配套评估程序。

正式实验完成后，在 `results/` 上传可复核的日志摘要、汇总表、图表与生成方式，
并在视频中展示动态 horizon 与累计推理次数。
